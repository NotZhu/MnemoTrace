# 契约：命名空间安全落盘

## 新目录映射

输入是逻辑 `tenant_id`，输出是数据根目录内的确定性目录：

```text
<sanitized-readable-prefix>--<sha256(tenant_id) first 16 hex>
```

- 摘要输入使用原始 UTF-8 字节，不先做字符删除或 Unicode 规范化。
- 可读前缀只用于排障，不参与唯一性；限制长度并只保留跨平台安全字符。
- 空白或没有安全前缀时使用固定 `namespace` 前缀。
- 路径拼接后必须验证真实父路径等于配置的数据根目录。

## 唯一目录与旧数据处理

服务始终只使用安全摘要目录，不回退至
`<tenant_id>` 或 `<tenant_id>.pkl`，不因旧目录存在而读取、写入、合并或删除其中内容。

摘要路径的最终真实目录项名称必须与生成名完全相同，拒绝同级链接和文件系统名称别名。
逻辑 ID 可以与另一个租户的存储目录名相同，但只能通过自身摘要映射访问存储。

旧数据如需保留，管理员须停止共享数据目录的进程并备份，结合历史配置确认真实归属后，
将明确选定的 JSONL 源库显式复制到该 namespace 尚不存在的摘要目录，验证后再处理旧来源；
pickle 转换工具已退役，服务不读取或转换旧 pickle，也不清理旧来源。

## 删除契约

- 删除目标只有当前租户的安全摘要目录，与读取路径一致。
- 删除前验证目标位于数据根目录内且没有目录别名。
- 绝不对数据根目录本身、其父目录或未验证路径执行递归删除。
- 删除完成后清除该租户热缓存，不影响其他租户。

## 验收样例

必须覆盖：`alice`、`a/b`、`ab`、`.`、`..`、`../outside`、绝对路径、前后空白、中文、组合 Unicode、
超长 ID，以及两个只在被旧实现删除的字符上不同的 ID。

还需覆盖旧账号名目录及 `.pkl` 候选存在时，读取为空、新写入仅进入摘要目录、重启恢复新数据、
清空只移除摘要目录，旧内容字节不变；以及 B 的逻辑 ID 等于 A 的摘要目录名时仍保持隔离。
