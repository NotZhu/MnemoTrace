# 数据生命周期指南

本指南供接入方和运维人员选择事实删除、会话擦除、空间清空或空间删除，并在请求完成后核对结果。 [HTTP 错误响应](../reference/http-api.md#错误响应) · [擦除与一致性边界](../architecture/memory.md#擦除与一致性边界)

## 选择操作

| 需求 | HTTP 请求 | 删除后的状态 |
| --- | --- | --- |
| 移除一条抽取结果，保留对话 | `DELETE /v1/spaces/{space_id}/facts/{fact_id}` | 删除事实、关联的向量、显著度、证据引用和相关审计。移除依赖该事实的画像条目。保留会话及其原文。 |
| 移除一段对话及其原文 | `DELETE /v1/spaces/{space_id}/sessions/{session_id}` | 删除目标会话、原文、写入任务和会话摘要。依赖这些原文的证据组和审计被清理，仍有独立证据支持的事实可以保留。 |
| 清空某个空间，继续使用原空间 | `POST /v1/spaces/{space_id}/purge` | 清空空间内的会话、原文、事实、搜索数据、审计、任务和派生数据。保留空间 ID、配置和嵌入空间登记。 |
| 移除空间及其中的数据 | `DELETE /v1/spaces/{space_id}` | 删除空间内容、空间登记及其嵌入空间登记。账号的 API 密钥仍可用于该账号下可访问的其他空间。 |

操作前，用同一账号的 API 密钥确认目标空间和资源 ID。四类请求均使用 Bearer 认证并发送空正文，清空空间还须发送 `Idempotency-Key`。成功返回 `204 No Content` 后，按下文发起新请求核对目标。 [核对操作结果](#核对操作结果) · [验证用例](../../tests/postgres/test_memory_http.py)

## 事实、证据与历史

**删除事实**适合纠正某个抽取结果。原文和原写入任务仍可读取。任务摘要记录当时的提交，事实和审计以新查询为准。该事实及引用它作为截止依据的相关审计会清理，仍存续的其他事实沿用其已提交的有效区间。

**擦除会话**以原文为起点。证据组只要引用该会话的一条原文，整组证据都会撤下。一个抽取事实还有其他完整证据组时可以保留，失去全部完整证据组时会被删除。比如两个会话各自完整支持“工作日骑车上班”，擦除其中一个会话后，仍可查到由另一场会话支持的事实。

历史召回使用当前存续的事实和有效期。擦除后的 `as_of` 查询遵循擦除后的数据范围。审计遇到来源被擦除时会删除相应记录，依赖已撤下事实的画像条目也会退出可见结果。 [证据组和审计回归](../../tests/postgres/test_erasure.py)

## 超时、重试与并发

- **清空空间的结果不明时，用原键重试。** 同一空间的同一幂等键只执行一次清空。若第一次已提交但响应丢失，重放返回 `204`，保留第一次清空之后的新写入。用户发起另一次独立清空时才使用新键。 [同键重放测试](../../tests/postgres/test_operations.py)
- **删除请求的结果不明时，先核对原目标。** 使用同一账号、空间 ID 和资源 ID 发起对应的详情查询。目标已消失时，重放删除可能返回 `404`。结合操作前的可见性、原响应或请求 ID 判断结果。
- **后台任务与已开始的读取有不同的完成边界。** 擦除会移除目标会话的写入任务，清空会移除目标空间中的任务。写入和派生数据在发布前会校验会话、租约或擦除代际。擦除提交前已读入快照的召回请求仍可能返回此前读取的证据，核对结果时应在操作完成后发起新请求。 [进行中写入测试](../../tests/postgres/test_operations.py) · [召回快照测试](../../tests/postgres/test_recall.py)

## 核对操作结果

| 操作 | 完成后发起的新读取 |
| --- | --- |
| 删除事实 | `GET /v1/spaces/{space_id}/facts/{fact_id}` 返回 `404 fact_not_found`。目标原先带敏感标记时，用 `include_sensitive=true` 按相同的可见性范围核对。原文仍可通过 `GET /v1/spaces/{space_id}/messages/{message_id}` 访问。 |
| 擦除会话 | 查询原会话、已知原文和写入任务 ID，分别返回 `404`。若事实由其他会话独立支持，读取事实检查保留下来的 `source_message_ids`。 |
| 清空空间 | 空间详情仍可读。如果清空后还没有新写入，会话、事实和任务列表的 `items` 为空，空间画像的 `profile` 为 `null`。用 `state=all&include_sensitive=true` 查询事实列表可覆盖历史及敏感事实。 |
| 删除空间 | `GET /v1/spaces/{space_id}` 返回 `404 space_not_found`。在同一账号下查询其他空间以核对操作范围。 |

`404` 表示资源不存在或对此账号不可见。用操作前确认过的账号和资源 ID 核对结果，保留 `X-Request-ID` 供排查。召回结果会受时点、筛选条件和预算影响，按资源 ID 查询适合验证删除的具体目标。

上述操作作用于 MnemoTrace 当前数据库中的数据。调用方已保存的响应、备份和外部日志按各自的管理流程处理。数据库备份入口见[部署与运维指南](../../deploy/README.md#停机备份与升级)。
