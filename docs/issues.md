## ISSUE-003：一次性决定进入长期偏好

**类型**：缺陷 · **范围**：事实提取、画像 · **优先级**：P1 · **状态**：待决策

### 现象与影响

原文只表达“本次部署决定使用关键词检索”，提取结果却可能被标为 `user / prefers / keyword retrieval`，进入正式画像。一次性的方案选择因此可能在之后的问答中被当作长期偏好使用。

会话结论中保存了正确的 decision，不会自动校正另一条 prefers 事实；两条写入路径需要保持含义一致。

### 原因与证据

`LLMExtractor.facts_from()` 接受模型给出的关系类型，画像构建再根据 prefers 等关系归类，当前路径没有再次判断原文的场景限制。合成复现证明的是“给定这样的提取结果会进入偏好”，尚未测量真实模型发生误判的频率。

默认 `remember(..., scope="auto")` 会先进行瞬态路由。“本次部署决定使用关键词检索。”中的“本次”命中瞬态标记，合成端到端调用返回 `scope=working`，长期事实数量为 0。给定提取结果的复现不代表所有默认写入都会进入画像；显式 `long`、导入以及未命中瞬态标记的表述需要分别验证。

### 处理要求

- 先确定一次性决定、长期采用规则和个人偏好的区分标准，再选择提取约束或画像筛选方案。
- 保留用户明确表达的长期技术偏好，不能把所有技术方案或单次提及一律排除。
- 如需修正已有事实，应保留原文、来源和变化历史，避免通过批量删除或改写关系掩盖误判。

### 验收标准

- 明确偏好、限定场景的决定、长期工作规则及混合表达能够分别处理。
- 分别覆盖默认 `auto` 路由、显式 `long`、导入和未命中瞬态标记的表述，区分写入路由与提取器的判断责任。
- 同一原文产生的会话决定与画像事实在主体、适用范围和时间上不矛盾。
- 用户手动设定、跨会话确认的信息及明确的长期偏好不被误删或降级。

**代码与证据**：[提取器](../mnemotrace/consolidate/llm_extractor.py)、[画像构建](../mnemotrace/consolidate/structured.py)、[合成复现](../results/engineering/open-issues/README.md#evidence-issue-003)。

## ISSUE-004：问答证据过宽且跨层重复

**类型**：缺陷 · **范围**：检索、证据组装 · **优先级**：P1 · **状态**：待处理

### 现象与影响

询问“我不喜欢吃什么”时，上下文可能同时包含同一空间内其他人物的饮食偏好、住址、摄影计划或技术方案。同一条信息还可能在画像、事实、偏好表、摘要和原文中重复出现。

这些材料实际进入答题模型的输入；仅折叠界面卡片不会减少模型收到的内容。问题影响证据范围与信噪比，实际准确率变化尚未量化，也没有据此确认跨命名空间泄露。

### 原因与证据

- 画像：默认加入当前叙事画像，未按本轮问题筛选其内部内容。
- 事实：混合检索返回排序靠前的候选，该返回位置缺少统一的最低问题相关性要求。
- 偏好表：以偏好关系、词项相关性和日期组织候选，人物与主题限定不足。
- 组装：各层局部去重不能保证同一信息在所有证据层之间只表达一次。

依据包括上下文估算样本和上述代码路径，尚无完整修复前后对照实验。界面中的上下文与原始对话 token 估算覆盖范围不同，不是实际计费量；原文片段数量也不限制整份证据上下文。

### 处理要求

按问题所问的人物、主题、关系和时间选择证据，相关性不足时不为凑数量补入材料。减少重复时保留必要的原文、来源和限定条件，继续使用事实与原文的混合证据。

### 验收标准

- 覆盖本人、明确询问他人、混合人物及混合主题的问题，证据归属清楚。
- “不喜欢番茄”与“喜欢番茄炒蛋的味道”等限定表达不被误合并或截掉条件。
- 简单问题减少无关与重复证据，多跳、聚合、时间更新和无答案场景仍保留所需材料。
- 比较实际选入的证据、答案正确性和统一口径的上下文估算，不以“必须短于原始对话”为唯一目标。

**代码与证据**：[证据组装](../mnemotrace/memory.py)、[混合检索](../mnemotrace/retrieve/hybrid.py)、[样本边界](../results/engineering/open-issues/README.md#evidence-issue-004)、[已有调用链验证](../results/engineering/README.md#maintenance)。

## ISSUE-005：会话结论同义改写后重复保存

**类型**：缺陷 · **范围**：会话结论 · **优先级**：P1 · **状态**：待决策

### 现象与影响

同一会话没有新增原文，反复总结时，模型仍可能用不同措辞重述同一结论，并新增为另一条 `Fact`，导致重复存储与统计膨胀。

重复总结也可能发现原文中此前遗漏的另一项决定或经验，因此不能把“第二次新增”一律当作重复，也不能直接禁用重复总结作为完整修复。

### 原因与证据

每次关闭会话都可能重新调用模型分析整个会话。跨调用去重主要比较同用户、同会话、当前有效结论的小写 `statement` 前 120 个字符，why 不参与键，也不判断语义等价。

假模型的合成复现得到新增数量 `[1, 1, 0]`：前两次同义改写各新增一条，第三次文字完全相同则被拦截。现有相同文字回归不能证明真实模型改写时也能去重。

SDK 的 CloseSessionResult 注释承诺“未变更的会话重复关闭不会新增”，Journal 的注释也将重复蒸馏称为无害空操作。这些保证超出当前去重能力，需要与实际行为保持一致。

### 处理要求

- 明确允许重复总结补漏，还是只在原文变化后再次提炼，并说明这对漏提取信息的影响。
- 区分相同文字、同义重复、真正补充和时间变化；相近但矛盾的结论不能合并。
- 保留手动修正、来源和双时间历史。原文追溯入口由 [ISSUE-009](#issue-009) 单独验收。
- SDK、页面说明和代码注释准确描述重复关闭的行为，不将文字去重表述为完整的会话级幂等保证。

### 验收标准

- 覆盖相同回复、同义改写、前缀相同但含义不同、真正新增及原文增长。
- 不同主体、不同时间或相互矛盾的结论不会被误合并。
- 手动编辑过的结论不会被重新生成的旧措辞覆盖，来源记录保持完整。
- 重复关闭的公开契约、界面说明与实际新增数量一致。

**代码与证据**：[结论提取](../mnemotrace/consolidate/outcomes.py)、[关闭会话](../mnemotrace/service.py)、[SDK 契约](../clients/typescript/src/types.ts)、[结论页面](../frontend/src/pages/Journal.tsx)、[合成复现](../results/engineering/open-issues/README.md#evidence-issue-005)。

## ISSUE-006：分类关键词误匹配

**类型**：缺陷 · **范围**：分类、画像 · **优先级**：P2 · **状态**：待处理

### 现象与影响

事实标签和画像偏好分组会因局部字串命中而分错类别，影响管理筛选与阅读。已合成复现的样例包括：

| 路径     | 输入                             | 当前分类 | 误命中           |
| -------- | -------------------------------- | -------- | ---------------- |
| 事实分类 | uses / storage engine            | 身份     | storage 中的 age |
| 画像分组 | prefers / team collaboration     | 饮食     | team 中的 tea    |
| 画像分组 | prefers / 整理资料               | 饮食     | 料               |
| 画像分组 | prefers / 流行的编程框架         | 音乐     | 流行             |
| 画像分组 | prefers / 保留事实和原始会话片段 | 影视     | 片               |

### 原因与证据

两套分类主要使用子串判断，英文缺少词边界，中文含单字或歧义词，并按固定顺序采用首个命中的类别。事实分类会保存为 `Fact.category`，画像分组则从关系与宾语临时计算，两者不能只修其中一处。

这些案例没有删除事实，也不证明存在隐私过滤或检索故障。敏感标记虽有相似匹配方式，仍需用独立样例核验。

### 处理要求

收紧中文单字、歧义词和英文词边界，明确多类别命中的优先级。分类证据不足时允许回退“其他”，不强行增加类别；同时明确已有分类与手动覆盖的更新策略。

### 验收标准

- 上述误判全部有回归，正常领域、复合关系和 favorite_ 等关系仍可识别。
- 分别验证持久化 `Fact.category` 与画像派生分组，修复范围不混淆。
- 不静默覆盖用户指定类别，不改写事实正文、来源和时间历史。

**代码与证据**：[事实分类](../mnemotrace/consolidate/classify.py)、[画像分组](../mnemotrace/consolidate/structured.py)、[合成复现](../results/engineering/open-issues/README.md#evidence-issue-006)。

## ISSUE-007：画像待确认候选入口不可达

**类型**：缺陷 · **范围**：画像 · **优先级**：P2 · **状态**：待决策

### 现象与影响

画像页面已经有待确认候选列表，以及确认、删除操作，但正常画像构建流程不能产生候选，因此这些入口无法正常出现。缺口位于候选进入规则，不等同于全部确认或删除功能缺失。

### 原因与证据

画像先要求 `_polarity(predicate)` 有结果，才判断偏好是否已确认；`_confirmed()` 对相同条件又直接返回 True，因此该路径中的 tentative 分支不可达。此判断不读取 `Fact.confidence`。

合成测试中，置信度为 1.0 和 0.3 的给定偏好均进入正式画像。这证明分组路径的限制，不证明真实模型已经产生弱推断。

### 处理要求

- 明确哪些信息属于用户直接陈述，哪些属于待确认的弱推断，再决定接通候选或调整能力说明。
- 不因只出现一次就把明确偏好降为候选，也不把来源数量或检索强化直接当作语义置信度。
- 明确确认与删除的持久化语义：当前确认会新增用户断言，删除会删除对应事实，均不只是切换界面标签。

### 验收标准

- 覆盖明确偏好、弱推断、手动设定及重复来源，候选进入规则与说明一致。
- 确认、删除后的列表、统计和重启状态一致，不意外形成重复的用户断言。
- 候选分层不隐式过滤正常记忆检索，也不影响独立的记忆冲突处理入口。

**代码与证据**：[画像构建](../mnemotrace/consolidate/structured.py)、[画像页面](../frontend/src/pages/Profile.tsx)、[合成复现](../results/engineering/open-issues/README.md#evidence-issue-007)。

## ISSUE-008：长期连接地址缺少选择与说明

**类型**：改进 · **范围**：接入配置 · **优先级**：P2 · **状态**：暂缓

### 现状与影响

接入命令的 API 地址默认来自 `VITE_API_BASE`，未配置时使用页面来源。通过开发页面接入时，保存的地址可能是 `http://localhost:5173`，形成“连接器 → Vite → 记忆服务”的长期依赖。

开发代理目前可用，不能仅凭端口号认定接入错误。风险在于关闭或更换 Vite 后，后端即使仍运行，已保存该地址的连接器也可能无法访问；这一停止代理场景尚未实测。

自动导入入口只生成 `mnemotrace-watch --install`，未传入当前服务地址或凭据。首次使用且没有环境变量或 watcher `key` 文件时，不能完成目标配置；已有 watcher 配置时，也不能保证导入当前页面所指的服务与空间。不能把 Codex MCP 已配置成功等同于 watcher 已使用相同目标。

Windows 的自动 scheduler 选择会落到 cron，当前没有 Windows 任务调度实现。界面提供 PowerShell 接入命令，不代表这条自动导入命令也已支持 Windows。

### 现有依据

Settings 将 apiBaseUrl() 交给安装命令生成器，连接器会持久保存传入地址。页面没有独立选择目标 API 地址的入口；当前服务健康状态也不能代替对另一个自定义目标的验证。

watcher 的 `_URL_DEFAULT` 来自环境变量或本机 8000 端口，`_resolve_key()` 读取参数、`key` 文件或环境变量；这条安装路径不从 Codex MCP 配置继承目标。依据为命令生成与解析调用链，实际安装和调度仍需验收。

### 处理要求

- 展示命令目标地址及其来源，允许单独填写连接器地址，不意外改变控制台自身请求的服务。
- 本机直连使用实际后端监听地址；远程部署使用连接器所在电脑可访问的地址。localhost 指向运行连接器的电脑，不能一律硬编码为 8000。
- 修改地址后同步更新 PowerShell、Bash 与复制内容，说明自定义目标是否已经验证。
- 自动导入命令明确目标地址、凭据来源与支持平台；执行前可核对其与当前空间的关系，不静默复用另一目标的配置。

### 验收标准

- 覆盖开发代理、同源部署、显式 `VITE_API_BASE` 和自定义远程地址。
- 地址格式、命令参数转义和两种终端的复制结果正确，测试不记录真实 `key`。
- 在后端持续运行时，直连配置不依赖 Vite；页面健康检查不能把不可达目标显示为已通过。
- 覆盖无既有配置、已有其他目标、环境变量覆盖和 Windows 场景；没有可用调度器时明确说明，不把打印 cron 行当作已完成自动导入安装。

## ISSUE-014：图谱截断后过滤导致当前关系缺失

**类型**：缺陷 · **范围**：图谱查询、展示 · **优先级**：P2 · **状态**：待处理

### 现象与影响

“仅当前”开启时，历史关系可能先占满查询上限，使仍有效的关系不进入返回结果，页面显示没有符合条件的图谱或缺少部分当前关系。

### 原因与证据

`GraphPage` 始终请求 `live_only=false, limit=120`，随后由浏览器过滤当前关系。后端 `graph_data` 收集到 120 条边便停止；在截断集合上本地过滤，不等价于在完整集合中过滤后再取 120 条。

合成数据含 121 条历史关系和 1 条当前关系时，该查询返回 120 条历史边，前端过滤后为 0；服务端使用 `live_only=True` 时返回 1 条当前边。

### 处理要求

在保持开关切换时布局稳定的前提下，通过分页、调整返回协议或在正确筛选范围内执行上限，保证当前关系不会被历史关系挤出。若结果并不完整，应明确显示范围，不能把截断后的空集解释为整个空间无匹配数据。

### 验收标准

- 覆盖超过 120 条历史关系、当前与历史交错、搜索及敏感过滤组合，当前关系可正确返回。
- 图谱、详情、统计和空状态使用一致的筛选范围，并准确说明截断或分页。
- 开关切换的坐标、相机与选中状态符合既定交互，不因补齐数据重复创建画布或泄漏资源。

**代码与证据**：[图谱页面](../frontend/src/pages/GraphPage.tsx)、[本地过滤](../frontend/src/lib/graphVisibility.ts)、[后端图查询](../mnemotrace/memory.py)、[截断复现](../results/engineering/open-issues/README.md#evidence-issue-014)。

## ISSUE-017：习惯正文忽略原语言展示字段

**类型**：缺陷 · **范围**：画像展示 · **优先级**：P3 · **状态**：待处理

### 现象与影响

事实已有中文展示句，画像习惯卡片却显示 `user weekly reads 示例书` 这样的内部拼接文本。原文和事实仍在，问题在于页面没有使用已有的原语言展示内容。

### 原因与证据

`Fact.text` 为空时会由主语、关系和宾语生成内部文本；提取器保存的原语言句子在 `Fact.display`。`display_of()` 优先使用 `display`，但习惯分支直接返回 `f.text`，前端再显示 `h.text`，绕过了展示逻辑。已有合成复现。

### 处理要求

统一采用原语言展示规则，保留规范关系、检索文本与来源；`display` 为空的事实使用合理回退，当前离线抽取也允许该字段为空。未知中文关系的回退仍可能带英文，需要单独核对，不能只换一次字段调用就宣告全部展示问题解决。

### 验收标准

- 覆盖中文 `display`、英文原文、`display` 为空的离线事实和未收录的长尾关系。
- 已有原语言展示内容得到优先使用，界面固定中文不强制翻译英文记忆。
- 展示修复不改写规范 `predicate`、事实正文、检索文本或 `provenance`。

**代码与证据**：[习惯分组](../mnemotrace/consolidate/structured.py)、[展示逻辑](../mnemotrace/localize.py)、[合成复现](../results/engineering/open-issues/README.md#evidence-issue-017)。

## ISSUE-020：删除单个会话

**类型**：新增功能 · **范围**：会话、存储 · **优先级**：P3 · **状态**：暂缓

### 需求与现有能力

需求是在会话列表删除指定会话。当前支持查看、切换和结束会话；结束会话用于整理并保留历史，与删除或清空整个空间不同。该需求保持暂缓，不增加删除入口。

### 实施前需明确

- 删除对象是否包括 `Episode`、会话摘要、会话结论、工作记忆和由它们支撑的长期 `Fact`。
- 多会话共同支撑的事实如何保留，来源、图关系、替代链与双时间历史如何更新。
- 是永久删除还是支持恢复，需要怎样的确认与权限校验。
- 删除当前选中会话后的选择行为，以及 `default` 会话 ID 与其已有内容如何处理。

### 处理要求

先确定上述产品与数据规则，再设计服务接口、存储处理和界面。会话索引由实际数据派生，不能只从前端列表隐藏卡片而宣称已删除。

### 验收标准

- 覆盖空间隔离、共享来源事实、当前会话和 `default` 会话。
- 删除或恢复后的列表、统计、原文与关联数据符合确定的范围，重启后结果一致。
- 不误删其他会话共同支撑的事实，不留下错误的来源或演化指针。
